## 二、文档清单（本仓库内）

| 文件 | 职责（单一） | 不负责 |
| --- | --- | --- |
| `../README.md` | 项目入口、为什么做、研究索引 | 任何设计细节 |
| `../.planning/STATE.md` | 当前阶段、硬性约束、下一步 | 设计内容（只做指针） |
| `PRD.md` | 定位、ICP、JTBD、范围、定价、风险、F9/F11 商家服务边界 | 交互细节、技术实现 |
| `UX-FLOWS.md` | 界面流程、状态机、空/错状态、商家工单与退费申请交互 | 数据结构、API、内部权限 |
| `TECH-DESIGN.md` | 数据模型、两个扩展、资产、校验、性能、App Pricing/Partner 同步与逻辑对象 | 界面文案、商务决策、退款政策 |
| `SECURITY-PCD.md` | 权限论证、数据清单、GDPR、审核、财务/工单/附件/Partner 数据边界 | 功能设计、完整工单状态机 |
| `QA-PLAN.md` | 三层测试用例、发布清单 | 需求定义（引用 `18`） |
| `FEATURES-V1.md` | V1 功能、定价、竞品基线的派生汇总 | 新定义（冲突以事实源为准） |
| `ADMIN-PRD.md` | 内部后台角色、页面、ADM 功能、指标与验收 | 重定义商家功能、实体或 GDPR 规则 |
| `PROTOTYPE-STACK.md` | 原型选型、素材接入、mock 设计、验证记录 | 生产实现与验收结论 |
| `AUDIT-PROTOTYPE.md` | 原型与设计差异、修复的核对记录 | 设计定义与最新验证状态 |

**原型边界**：`../prototype/` 仅用于 mock 交互验证；不代表已具备 Shopify、后端、权限或生产能力。修改时只读任务涉及的源码/测试；不要默认读取全部截图、SVG、锁文件、`node_modules/` 或 `dist/`。构建和交互测试的本次结果以实际运行为准，历史报告不能代替复测。

**边界原则**：同一个事实只在一份文档里定义，其他文档用指针引用。发现重复即视为缺陷。
